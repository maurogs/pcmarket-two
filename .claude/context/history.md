## 2026-11-12 — Phase 1b resume: review fixes
- Fixed the `FrozenError` raised when destroying a published listing with photos: `Listing#reopen_for_review_after_photo_change!` now returns early unless the record is still `persisted?`, so the photo `after_commit :destroy` callbacks no longer try to update the already-destroyed (frozen) listing.
- Rewrote `Listing.with_specs` to use only jsonb containment: each value is matched with `specs @> '{"key":"value"}' OR specs @> '{"key":["value"]}'`. Both predicates are served by the `jsonb_path_ops` GIN index on `specs`; the old `specs -> ? @> ?` predicate could not use it.
- Fixed `Listing.sorted_by(:relevance)`: it now checks `all.respond_to?(:with_pg_search_rank)` (the current relation) instead of the `Listing` class, so a pg_search relation keeps its rank ordering while plain relations still fall back to newest.
- Extended `20261112110300_create_listings.rb` with a partial newest-first index on `published_at` (`status = 'published'`, `published_at DESC`, name `index_listings_on_published_at_published`) and a plain `listing_tags.tag_id` index for reverse tag lookups. `down` is unchanged because `drop_table` removes both.
- Added regression tests: slug format, material edits via description/specs/category, photo removal, destroying a published listing with photos (counters decrement, no raise), explicit array-valued `with_specs`, oversized photo rejection, descendant depth refresh after reparenting, locale currency formatting (es/en) and the verified-email OmniAuth linking path.

## 2026-11-12 — Phase 2: browsing, search, filters and listing detail
- Added locale-scoped public routes: `resources :categories, only: :show, path: "c"`, `resources :listings, only: [:index, :show], path: "l"` and `get "search" => "listings#index"`; FriendlyId `history` on Category and Listing, with 301 redirects when an old slug is requested.
- Added `ListingSearch` (`app/queries/listing_search.rb`): visible-only relation, full-text search, category scoping, euro price range, conditions, whitelisted category specs, tags, ES province, free shipping, all five sorts and Pagy pagination. Invalid values are ignored. Facets and condition counts are computed in one SQL round trip over a materialised filtered CTE using `jsonb_each`/`jsonb_array_elements_text`; counts are cached for 5 minutes with a normalized key plus `listings/version`, which Listing touches after commit. Facets count the fully filtered relation (including an attribute's own selection) so zero-result options can be disabled.
- Added `Listing.with_card_includes` / `with_detail_includes`, `similar_to` and `more_from_seller` scopes, `publicly_visible?` / `visible_to?`, and `DeliveryEstimate` (business-day handling + 2–4 business-day delivery, weekend-aware).
